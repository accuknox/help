### API Security

Wider OWASP API Top 10 coverage and the eBPF collector were demoed on 31 July, but naming and the
screen flow for test roles were flagged for rework, and the broken BOLA detail is unresolved.
Do not write final copy or capture screenshots until the revised flow lands.

Draft copy from the 31 July demo, held back until the flow is final:

> API traffic is captured and grouped into collections by host. You then define test roles, where
> each role is a user identity the scanner runs requests as. Authorization tests such as Broken
> Object Level Authorization need two roles, a primary role standing in for the user who owns the
> resource and an attacker role standing in for a different authenticated user who should not
> reach it. A role authenticates either with a token you supply or with a token already seen in
> the captured traffic. During the scan, the scanner replays and modifies requests from the
> collection to check whether the API enforces authentication and authorization. Results appear
> on the findings screen under the API scan data type.

### Known bug: bulk accept on stable policies

Accepting changes for a policy in a stable state (nothing pending) incorrectly activates it, and
"Accept All" applies to stable policies instead of only those with pending changes. The
"Policy Import, Export, and Bulk Actions" section above works around this by telling users to
filter to changed policies first. Remove that workaround sentence once the bug is fixed.
