## API Security

### Wider OWASP API Top 10 Coverage

The API security scanner moves onto an open-source test library so it covers more of the OWASP API Top 10.

From the 31 July demo, the authenticated scan flow works like this. API traffic is captured and grouped into collections by host. You then define test roles, where each role is a user identity the scanner runs requests as.

Authorization tests such as Broken Object Level Authorization need two roles: a primary role standing in for the user who owns the resource, and an attacker role standing in for a different authenticated user who should not reach it. A role authenticates either with a token you supply or with a token already seen in the captured traffic. During the scan, the scanner replays and modifies requests from the collection to check whether the API enforces authentication and authorization. Results appear on the findings screen under the API scan data type.
