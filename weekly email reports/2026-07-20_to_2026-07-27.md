# Weekly Help Documentation Updates

**Period covered:** 2026-07-20 to 2026-07-27
**Subject line used:** Weekly Help Documentation Updates (Last 7 Days)

## Overview

This week's work centered on cloud security posture management, with a brand new IAM Permissions Reference section covering AWS, Azure, and GCP. Five new pages went live: four permission pages plus a Data Retention Policy page under Resources. The permissions reference answers one of the most common security-review questions we get, namely exactly what access AccuKnox asks for and why, backed by a full per-permission list for each cloud. Two broken or outdated download links were also corrected in the ServiceNow and Jenkins integration guides.

## New Documentation

**Least-Privilege Permissions Reference (Overview)**

https://help.accuknox.com/how-to/cspm-permissions-overview/

The entry point for the new IAM permissions section. States plainly that every permission the CSPM scanner requests is read-only, shows the permission count per cloud (AWS 403, Azure 209, GCP 901), and explains what happens if a customer denies one: a blind spot for that service, not a broken scan. Read this first before pointing a prospect at a specific cloud page.

**AWS IAM Permissions Reference**

https://help.accuknox.com/how-to/cspm-permissions-aws/

All 403 read-only AWS IAM permissions the scanner requests, grouped by service, each with a plain-English description of what it does and a hover badge explaining why AccuKnox needs it. Only `List`, `Describe`, and `Get` calls, with no write, delete, or data-download access. Useful for Solution Engineers and Support answering security-team questions during AWS onboarding.

**Azure Permissions Reference**

https://help.accuknox.com/how-to/cspm-permissions-azure/

The 209 read-only Azure permissions used by the CSPM scanner, in the same grouped-by-service format with per-permission rationale. Hand this to Azure cloud admins who need to review or justify the access before approving onboarding.

**GCP Permissions Reference**

https://help.accuknox.com/how-to/cspm-permissions-gcp/

The full 901 read-only GCP permissions, grouped by service with rationale on each. This is the largest of the three lists and is the reference to use when a GCP security review asks for a line-by-line breakdown.

**Data Retention Policy**

https://help.accuknox.com/resources/data-retention-policy/

A single table covering how long AccuKnox keeps each data type: CSPM fixed findings and deleted assets (180 days), CDR cloud logs (90), CWPP alerts (180) and telemetry (30), ASPM findings and assets (180), EventTrail activity logs (180), reports (180), SIEM logs (180), and raw scanner JSON in S3 (365). It also notes that retention can be adjusted for enterprise or contractual requirements. Expect this page to come up in procurement, compliance, and audit conversations.
