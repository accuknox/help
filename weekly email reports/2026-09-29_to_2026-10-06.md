# Weekly Help Documentation Updates

**Period covered:** 2026-09-29 to 2026-10-06
**Subject line used:** Weekly Help Documentation Updates (Last 7 Days)

## Overview

This week AccuKnox published 8 new pages and moved 2 existing pages. Secrets Manager grew from one overview and one deployment guide into a full product section with 7 new pages. AI Security gained an Azure Organization onboarding page, and the Azure permission lists changed for both Azure paths. The Deployment Models page moved to Resources and now has a section for each of the four deployment options. Four existing pages gained short product tour videos.

## New Documentation

**Azure Organization AI/ML Cloud Onboarding**
URL: https://help.accuknox.com/how-to/aiml-azure-org-onboard/

This page connects a whole Azure Organization to AccuKnox AI Security from one connection. The customer picks the Management Groups and Subscriptions in scope, and a Terraform script connects them. It also covers approving the Graph permissions on the app registration. Send it to customers with many Azure subscriptions. Customers with one subscription still use the standalone page.

**Secrets Manager Architecture**
URL: https://help.accuknox.com/secrets-manager/architecture/

This page shows what runs where. Applications on any cluster, VM or pipeline prove their identity, get a short-lived token and read their own secrets over TLS. It lists the auth method for each kind of caller and the three nodes that share one encrypted store. Solution Engineers can use its diagrams in technical calls.

**Air-Gapped Deployment (Secrets Manager)**
URL: https://help.accuknox.com/secrets-manager/air-gapped/

This page installs Secrets Manager on a cluster with no internet access. The customer moves the chart and images inside once, mirrors them into an internal registry and unseals with their own key holders. Read it for any defense, federal or regulated customer.

**High Availability, Backup and Day 2 Operations**
URL: https://help.accuknox.com/secrets-manager/high-availability/

This page covers a three-node setup that keeps serving when one node fails, plus snapshots to object storage every 15 minutes. It warns that a restarted node comes back sealed and needs 3 of the 5 unseal keys. Support should read it before any production go-live.

**Connect Applications to Secrets Manager**
URL: https://help.accuknox.com/secrets-manager/connect-applications/

This page helps a customer choose between two ways to deliver secrets to an application. One is a direct SDK or REST API call. The other is the External Secrets Operator. Both can run side by side in one cluster.

**Direct SDK and REST API Integration**
URL: https://help.accuknox.com/secrets-manager/sdk-integration/

The application reads the secret itself and keeps it in memory, so no Kubernetes secret or environment variable holds a copy. Any Vault client library works, because Secrets Manager is API-compatible with HashiCorp Vault. Use it for the strictest customers and for apps on virtual machines.

**External Secrets Operator Integration**
URL: https://help.accuknox.com/secrets-manager/external-secrets/

This page syncs a Secrets Manager value into a Kubernetes secret, so an application reads it with no code change. It explains the three objects that do the work and how to install and set them up. Use it when the customer cannot change application code.

**Sync a Database Password Into a Kubernetes App**
URL: https://help.accuknox.com/secrets-manager/use-case-wordpress-mysql/

This is a worked example with WordPress and MySQL, and it includes a two-minute demo video. The database password moves into Secrets Manager and stays in step with the Kubernetes secret. Customer Success can send it as a proof of value.

## Updated Documentation

**Deployment (previously Deployment Models)**
URL: https://help.accuknox.com/resources/deployment/

The page now has a comparison table and a diagram for each option: SaaS, Your Cloud, On-Premises and Air-Gapped. The table shows where the control plane runs, the data path and the best fit. The page also maps the four commercial offerings to these models. Use it to answer data residency questions.

**AccuKnox Secrets Manager Overview**
URL: https://help.accuknox.com/secrets-manager/overview/

The page was rewritten as the starting point for the section. It lists what Secrets Manager stores, how each app reads only its own paths, and links to deployment, connection and use-case pages. It requires Kubernetes 1.30 or later.

**Secrets Manager Deployment Guide**
URL: https://help.accuknox.com/secrets-manager/deployment/

The guide was extended and now points to the new air-gapped, high availability and connection pages.

**Secrets Manager FAQs**
URL: https://help.accuknox.com/faqs/secrets-manager/

Four new answers: which clusters it runs on, SDK or External Secrets Operator, how a changed secret reaches a running app, and running with no internet access.

**Azure AI/ML Cloud Onboarding (Standalone) and Azure CSPM prerequisites**
URLs: https://help.accuknox.com/how-to/aiml-azure-onboard/ and https://help.accuknox.com/how-to/cspm-prereq-azure/

The custom role is now one JSON block with both action and data action lists. It adds permissions for Foundry Agents, which AI/ML red teaming needs. Several key listing permissions and some Graph permissions were removed. Customers who onboarded earlier should compare their role with the current page.

**Power Platform Integration (previously Copilot Studio Integration)**
URL: https://help.accuknox.com/integrations/copilot-studio/

The extra permission list was cut to one Application permission, `AuditLogsQuery-CRM.Read.All`, so the setup asks for less access. The page is now called Power Platform Integration, and the home page, the AI integrations page and the Azure AI/ML onboarding tip use the new name. The steps did not change.
