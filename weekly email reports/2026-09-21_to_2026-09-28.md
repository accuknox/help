# Weekly Help Documentation Updates

**Period covered:** 2026-09-21 to 2026-09-28
**Subject line used:** Weekly Help Documentation Updates (Last 7 Days)

## Overview

This week AccuKnox published three new pages and a new product section for Data Security Posture Management (DSPM). DSPM finds sensitive data in cloud storage, databases and SaaS apps. The AI Security section now has two AWS onboarding paths, one for an AWS Organization and one for a standalone account. The IDE extension page now covers IntelliJ as well as VS Code and Cursor. The CI/CD support matrix gained a full table of which scan types run on which platform, and the sample reports page gained an SBOM Risk report.

## New Documentation

**Data Security Posture Management (DSPM) Overview**
URL: https://help.accuknox.com/getting-started/dspm-overview/

This page introduces DSPM. The scanner runs on a machine in the customer's own cloud account, in the region that holds the data. It reads a sample with read-only access and sends only a findings file to the AccuKnox console. The page lists the supported data stores (S3, Azure Blob and ADLS Gen2, RDS and Aurora, Azure SQL, Cosmos DB, MongoDB, DocumentDB, Google Workspace Drive and Salesforce). It also lists what is not supported (Google Cloud Storage, SMB and NFS shares, Oracle and Snowflake), the 283 data classes, 62 country packs and the compliance mapping to frameworks such as GDPR. Solution Engineers should read it before any DSPM conversation, because the data residency answer and the unsupported list come up early.

**Onboard the DSPM Scanner**
URL: https://help.accuknox.com/getting-started/dspm-onboarding/

This page sets up the scanner in five steps: create a token and label, create the VM, grant read-only access per data store, configure the scanner, and run the first scan. The grant tables cover AWS, Azure, databases and SaaS apps, and a Kubernetes CronJob option exists for EKS and AKS. The VM needs no inbound connections and only port 443 outbound. Customer Success and Support should use it for any DSPM rollout.

**AWS Standalone AI/ML Cloud Onboarding**
URL: https://help.accuknox.com/how-to/aiml-aws-standalone-onboard/

This page connects one AWS account, outside an AWS Organization, to AccuKnox AI Security. A Terraform script creates the access keys, and the customer pastes them into the console. The page lists every AWS permission the keys need, including the Amazon Bedrock permissions. Send it to customers who want AI/ML asset discovery on a single account.

## Updated Documentation

**AWS Organization AI/ML Cloud Onboarding**
URL: https://help.accuknox.com/how-to/aiml-aws-onboard/

This page was rewritten. The old flow created an IAM user with access keys by hand. The new flow uses one CloudFormation stack that creates a read-only role in the Management Account and deploys the same role to member accounts. AccuKnox gets temporary credentials, so the customer stores no long-lived keys. The page lists the prerequisites, including trusted access between CloudFormation StackSets and AWS Organizations. Customers with many AWS accounts should use this page. The page title changed from "AWS AI/ML Cloud Onboarding".

**AccuKnox Code Security for VS Code, Cursor, and IntelliJ**
URL: https://help.accuknox.com/integrations/vscode-code-security/

The IDE extension now runs in IntelliJ through a separate plugin, installed from **Settings > Plugins**. The scanner CLI, the Access Key and the sign-in steps are the same as in VS Code. Only the menu names differ.

**CI/CD Support Matrix**
URL: https://help.accuknox.com/support-matrix/cicd-support-matrix/

A new table lists each scan type (SQ SAST, SAST, DAST, IaC, container, secret, xBOM, unified scan, CX scan, pipeline script and app based) against nine CI/CD platforms. Jenkins DAST now scans login-protected applications as well as public ones. The version numbers on the platform links were removed. A second table confirms the IDE extension for VS Code, Cursor and IntelliJ. Use this page to answer "does scan X run on platform Y" in one look.

**GitHub Unified Code Analysis Tool**
URL: https://help.accuknox.com/integrations/github-unified-code-analysis-tool/

The page now describes the six scans by what they do, and it no longer names the open-source tool behind each scan. Every screenshot now has a description of what it shows.

**Sample Reports**
URL: https://help.accuknox.com/resources/sample-reports/

A new SBOM Risk sample report is available as a PDF: https://help.accuknox.com/resources/assets/SBOM_Report.pdf. Share it with prospects who ask what an SBOM report looks like.
