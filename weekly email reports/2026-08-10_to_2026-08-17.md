# Weekly Help Documentation Updates

**Period covered:** 2026-08-10 to 2026-08-17
**Subject line used:** Weekly Help Documentation Updates (Last 7 Days)

## Overview

A heavy week, and the biggest documentation change in months. Secrets Manager now has its
own product section with six pages, including four hands-on use case guides that did not
exist before. Shadow AI Discovery got its first dedicated page, and seven onboarding
guides now say which AI Security features they turn on. Two new deployment guides went
live: OpenShift VM scanning and source code scanning through the AccuKnox app. Nine pages
are newly visible in total, and the v3.6 release notes gained the full Security Graph
walkthrough plus a highlights video.

## New Documentation

**AccuKnox Secrets Manager Overview**

https://help.accuknox.com/secrets-manager/

The landing page for Secrets Manager as a standalone product. It explains central storage
for passwords, API keys, tokens, and certificates, and states plainly that Secrets Manager
installs on its own with no CNAPP subscription. Read this before you position Secrets
Manager on a call, because the separate-product point comes up often.

**Secrets Manager Deployment Guide**

https://help.accuknox.com/secrets-manager/deployment/

A full Kubernetes install walkthrough using the Helm chart, covering system and cluster
prerequisites, initialization, unsealing, and the first UI sign-in. It replaces the older
on-prem deployment page and roughly triples its depth. Solution Engineers running a
proof of concept should work from this page.

**Storing Secrets in the KV Engine**

https://help.accuknox.com/secrets-manager/kv-secrets/

Shows how to enable the key/value engine, then create, read, version, and delete a secret
from the UI. It covers version history and rollback. This is the starting use case for
any Secrets Manager demo.

**Encryption as a Service, Transit Secret Engine**

https://help.accuknox.com/secrets-manager/transit/

Explains how an application sends plaintext, gets ciphertext back, and stores only the
ciphertext, so developers never handle encryption keys. It also covers signing, verifying,
and HMAC checks. Useful when a prospect asks how AccuKnox removes crypto work from the
application team.

**TOTP Authenticator**

https://help.accuknox.com/secrets-manager/totp/

Covers the TOTP engine in both modes: generating rolling 6-digit codes as a replacement
for a phone authenticator app, and validating codes that users submit. The strong angle
here is shared team accounts, such as a cloud root account, where policies control who may
produce a code and every request is audited.

**Sharing Secrets Within an Organisation**

https://help.accuknox.com/secrets-manager/sharing-secrets/

A four-step guide to giving each teammate a scoped account with a least-privilege policy,
then proving the scope holds. It directly answers the "stop passing credentials in chat"
objection, and it shows that revoking access takes one policy change.

**Shadow AI Discovery**

https://help.accuknox.com/use-cases/shadow-ai-discovery/

The first dedicated page for Shadow AI Discovery. It explains how AccuKnox finds and
classifies AI assets across cloud and on-prem infrastructure without a declared inventory,
and maps each one to a type such as AI Agent, AI Gateway, AI Inference Engine, or MCP.
Cloud assets appear under the Managed tab and on-prem assets under the Unmanaged tab. This
is now the reference page for any AI discovery conversation.

**OpenShift VM Scanning (Agentless)**

https://help.accuknox.com/how-to/vm-security/agentless/openshift-vm-scanning/

Covers agentless vulnerability scanning of Red Hat OpenShift Virtualization VMs. You
install one operator on the cluster, create a schedule, and the operator snapshots and
scans each VM on your chosen cron expression, then cleans the snapshots up. Nothing is
installed inside the VMs, and nothing leaves the cluster except the findings.

**Connect GitHub, GitLab, or Bitbucket for Source Code Scanning**

https://help.accuknox.com/how-to/code-source-onboarding/

This page was written some time ago but stayed hidden from the site navigation. It is now
published, and the content was rewritten and expanded. It covers the three-step Connect,
Repo and Branches, Scan wizard, per-repository scan overrides, auto connect for new
repositories, and how to read results. The selling point is that SCA, Secrets, SAST, SBOM,
and IaC scans all run on the AccuKnox platform with no pipeline changes.

## Updated Documentation

**AccuKnox v3.6 Release Notes**

https://help.accuknox.com/getting-started/3.6-release/

The Security Graph section was rewritten and expanded well beyond its original two
sentences. It now documents both entry points, the asset graph from Inventory and the
findings graph from Issues, with a worked EC2 example showing how an attacker pivots
through attached IAM identities. A v3.6 highlights video was embedded at the top of the
page. The placeholder release date was removed.

**AI/ML Onboarding for AWS, Azure, and GCP**

https://help.accuknox.com/how-to/aiml-aws-onboard/
https://help.accuknox.com/how-to/aiml-azure-onboard/
https://help.accuknox.com/how-to/aiml-gcp-onboard/

All three pages now open with a panel naming what cloud onboarding turns on: Model and
Data Security, Shadow AI Discovery, and Prompt Firewall for Cloud Assets. Each links to
the new Shadow AI Discovery page. The GCP page carries a further change worth knowing
about, described below.

**GCP Prerequisites and GCP AI/ML Onboarding, Vertex AI renamed**

https://help.accuknox.com/how-to/cspm-prereq-gcp/
https://help.accuknox.com/how-to/aiml-gcp-onboard/

Google renamed the service, so every reference to Vertex AI became Agent Platform. The
required APIs changed with it. Agent Platform API and the new Agent Registry API replaced
the Vertex AI API, and the custom role now needs Agent Platform Viewer and Agent Registry
Viewer. Anyone walking a customer through GCP onboarding should reread these two pages,
because the old console names no longer match.

**Kubernetes, Linux, and Windows Onboarding**

https://help.accuknox.com/how-to/k8s-security-onboarding/
https://help.accuknox.com/how-to/vm-security/agent-based/linux/
https://help.accuknox.com/how-to/vm-security/agent-based/windows/

Each page now explains that the same onboarding flow also powers Shadow AI Discovery on
that target. The scanner does package-level discovery, so AI frameworks, SDKs, and model
runtimes get classified and reported under the Unmanaged tab with their vulnerability
data. The VM pages call out agentic runtimes such as OpenClaw, which AccuKnox reports as
an unmanaged asset mapped to its parent host.

**Cloud VM Scanning**

https://help.accuknox.com/how-to/vm-security/agentless/cloud-vm-scanning/

The supported platform list corrects the spelling of OpenShift, and the page notes that
OpenShift uses an operator rather than the Terraform flow the public clouds use.

**CyberArk Conjur**

https://help.accuknox.com/use-cases/cyberark-conjur/

A worked example on this page contained real private key material. It was replaced with a
placeholder. No steps changed, so anyone who followed the guide before is unaffected.

## New Documentation Sections

**Secrets Manager** is now a top-level product section rather than three pages parked
inside Getting Started. It holds an Overview, a Deployment Guide, and a Use-Cases group
with four guides: storing secrets, the Transit engine, TOTP, and sharing secrets across an
organisation. The move reflects how Secrets Manager is sold, as a product that installs
and runs on its own.

## Navigation Changes

Three things moved this week. Existing links keep working in every case, because
redirects are in place.

**Secrets Management** left Getting Started and became the Secrets Manager section. The
old Overview page now lands on the new Overview, and the old On-Prem Deployment Guide
lands on the new Deployment Guide. The two Secrets Manager buttons on the documentation
home page point at the new location.

**Event Trail Logs** moved from Getting Started into Use-Cases.

**SARIF Findings** moved from Getting Started into the ASPM group under Use-Cases.

Two new pages joined existing groups. OpenShift VM Scan sits under VM Security, Agentless.
Shadow AI Discovery sits under AI Security. Connect Source Code (App Based) appears under
Application Security (ASPM) for the first time.

## This Week's Highlights

- Secrets Manager became its own product section, with four new use case guides that make
  it demonstrable end to end for the first time.
- Shadow AI Discovery got a dedicated page, and seven onboarding guides now point to it.
- Source code scanning through the AccuKnox app is published and visible in navigation.
- OpenShift VM scanning is documented, closing the last gap in agentless VM coverage.
- Vertex AI is now Agent Platform across the GCP guides, and the required APIs changed.
