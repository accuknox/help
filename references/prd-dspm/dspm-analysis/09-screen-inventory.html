1. Connector Wizard

Problem statement: Buyers lose confidence when onboarding feels opaque or permission-heavy.

Primary persona: Cloud security architect or platform engineer.

User goal: Connect an environment quickly and understand whether the scan will produce reliable results.

Data requirements: Connector catalog, required IAM scopes, validation results, estimated scan time, source counts, regional selection.

UI composition: Four-step wizard, progress rail, validation table, scan estimate side panel, help drawer.

Key interactions: Select connector, validate credentials, choose scope, schedule scan, save presets.

States: Empty, validating, ready, partial permissions, failed validation, scan queued.

Telemetry: Connector selected, validation passed or failed, scan started, abandonment step, retry count.

Integrations: AWS IAM, GCP IAM, Azure permissions, Snowflake, BigQuery, ticketing for failed setup.

Acceptance criteria: User can reach a clean scan-ready state in under five minutes for a supported preset and always sees why a validation failed.

Prompt for design and prototyping

Design a premium light-theme connector wizard for AccuKnox DSPM with enterprise density and clear safety cues. Include AWS and GCP presets, permission validation, estimated time to first insight, and a help drawer explaining why each scope is needed. The experience should reduce onboarding anxiety and feel more explicit than a generic cloud setup form.

Prompt for engineering implementation

Implement a multi-step connector onboarding flow with async validation, step persistence, resumable drafts, and typed connector schemas. Support connector presets, permission checks, scan estimation, and structured telemetry. Build the UI so failed validation messages map directly to missing scopes and recommended fixes.

2. Data Estate Dashboard

Problem statement: The first screen must prove value immediately or the product feels like another scanner.

Primary persona: Security analyst, security manager, CISO.

User goal: Understand overall data risk posture and decide where to drill in first.

Data requirements: Risk score, sensitive asset counts, exposed records, over-permissioned identities, trend history, compliance posture, top business units.

UI composition: KPI ribbon, trend chart, business-unit heatmap, urgent action rail, compliance scorecards.

Key interactions: Filter by cloud, business unit, framework, severity; drill into critical risks; save dashboard view.

States: First scan ready, filtered, loading, stale data, incident spike, no critical issues.

Telemetry: Filters used, drilldowns launched, widget engagement, saved views, export attempts.

Integrations: Asset inventory service, risk scoring engine, compliance mappings, report export service.

Acceptance criteria: A new user can identify the top three current risks and their business impact in under 60 seconds.

Prompt for design and prototyping

Create a flagship AccuKnox DSPM dashboard in a light theme with a top KPI ribbon, left trend chart, central risk heatmap, right urgent actions rail, and a bottom regulator readiness band. It should feel denser and more real than a marketing dashboard, while staying easier to scan than a legacy enterprise console.

Prompt for engineering implementation

Build a dashboard page composed of independently refreshable widgets backed by typed summary APIs. Support cross-widget filtering, saved views, role-based defaults, and graceful empty or stale states. Expose widget metadata for future report exports and scheduled summaries.

3. Sensitive Data Explorer

Problem statement: Analysts need a fast way to locate high-value assets without memorizing storage hierarchies.

Primary persona: Security analyst, data steward.

User goal: Search and filter sensitive assets by type, owner, cloud, and business context.

Data requirements: Asset metadata, sensitivity labels, owner, business domain, confidence score, last scanned timestamp, location.

UI composition: Search bar, left filter rail, center results table, right quick detail drawer.

Key interactions: Search, facet filtering, bulk selection, open asset detail, compare similar assets.

States: Empty query, filtered results, zero matches, stale metadata, bulk selected.

Telemetry: Query terms, filters, asset opens, bulk actions, sorted columns.

Integrations: Discovery index, classification service, ownership catalog, CMDB or data catalog if present.

Acceptance criteria: User can locate all assets tagged as critical PII in a chosen business unit in under 30 seconds.

Prompt for design and prototyping

Design a sensitive data explorer for AccuKnox DSPM with enterprise-grade search, faceted filters, and a quick detail drawer. Make the table feel trustworthy and dense, but not cluttered. Highlight owner, sensitivity, cloud location, last scan, access count, and regulator impact.

Prompt for engineering implementation

Implement a server-driven search and filter experience for sensitive assets with pagination, faceted counts, sorting, and optimistic URL state. Add keyboard-friendly search, bulk actions, and a quick detail drawer fed by a lightweight asset summary endpoint.

4. Risk Prioritization Board

Problem statement: Findings lists often feel noisy and arbitrary.

Primary persona: Security analyst.

User goal: Triage the highest-value issues first with confidence in the priority model.

Data requirements: Severity, business impact, access breadth, public exposure, exploitability inputs, compliance impact, suggested fix.

UI composition: Filter rail, ranked table, explainability panel, bulk action toolbar.

Key interactions: Sort by priority reason, open detail, assign owner, suppress false positive, compare findings.

States: Default ranking, filter-applied, grouped by reason, suppressed, assigned.

Telemetry: Ranking overrides, sort choice, filters, assignments, suppression rate.

Integrations: Risk engine, remediation workflows, identity service, ticketing.

Acceptance criteria: Top ranked issues always show why they are ranked high and what the next action should be.

Prompt for design and prototyping

Design a risk prioritization board that feels transparent rather than mysterious. Each finding row should show why it is urgent: sensitive data type, access exposure, exploitability context, and compliance impact. Add an explainability drawer that makes the scoring model understandable to a human reviewer.

Prompt for engineering implementation

Implement a ranked findings board backed by a scoring API that returns both score and explanation fields. Support server-side filtering, grouping, assignment, suppression, and audit logging. Preserve filter state in the URL and expose machine-readable score breakdowns for future automation.

5. Risk Detail

Problem statement: Analysts need one place to understand cause, impact, and next action for a single risk.

Primary persona: Security analyst, cloud security architect.

User goal: Understand the full context of a finding and choose the right remediation path.

Data requirements: Asset metadata, sensitivity evidence, exposure path, identity context, timeline, related findings, recommendation set.

UI composition: Summary header, tabbed context areas, right recommendation rail, lower related-issues panel.

Key interactions: Tab switching, evidence expand, open access graph, open lineage, start remediation.

States: Normal, evidence unavailable, recommendation pending, resolved, exception granted.

Telemetry: Tabs visited, evidence views, remediation launches, related issue pivots.

Integrations: Asset detail service, lineage service, graph service, remediation engine.

Acceptance criteria: User can understand root cause and choose a next action without leaving the page.

Prompt for design and prototyping

Design a finding detail page for AccuKnox DSPM with a strong summary header, tabs for asset context, access, lineage, compliance impact, and remediation. Use a right-side recommendation rail that always shows the next best action and estimated risk reduction.

Prompt for engineering implementation

Build a finding detail route with typed tab content, lazy-loaded heavy panels, and a persistent action rail. Ensure all context panels share the same finding identity and update in sync when filters or scope change. Log every remediation launch and evidence expansion for auditability.

6. Access Graph

Problem statement: Access risk is hard to understand in flat tables.

Primary persona: Security analyst, identity engineer.

User goal: Visualize who can reach sensitive data, through which permission path, and how to reduce that exposure.

Data requirements: Assets, identities, groups, roles, inherited grants, external links, blast-radius metrics.

UI composition: Graph canvas, legend, path inspector, identity summary, action drawer.

Key interactions: Hover node, expand path, isolate edge, filter node type, send path to remediation.

States: Single-path focus, graph expanded, filtered, large-graph sampling, no graph data.

Telemetry: Node selection, path isolation, graph filters, remediation launches.

Integrations: Identity graph service, access analytics engine, remediation workflows.

Acceptance criteria: User can identify the highest-risk access path and route it to remediation in one flow.

Prompt for design and prototyping

Design an access graph for AccuKnox DSPM that is readable by humans, not just impressive as a diagram. Distinguish asset, user, group, role, service account, and external link nodes. Provide a strong path inspector and an action drawer for rightsizing or review.

Prompt for engineering implementation

Implement an interactive graph view with performant path expansion, large-graph virtualization, and path isolation. Support node-type filters, hover details, and an action drawer that can launch remediation or owner review workflows with preserved graph context.

7. Lineage Explorer

Problem statement: Users need historical movement and transformation context to understand how risk evolved.

Primary persona: Security analyst, compliance analyst.

User goal: Trace how data moved, changed, or was accessed over time.

Data requirements: Event history, movement path, timestamped actions, source and destination systems, actor context.

UI composition: Timeline on top, lineage graph in the center, event details on the right.

Key interactions: Playback timeline, pivot to event detail, filter by actor or system, export trail.

States: Playback active, filtered, export-ready, no retained events.

Telemetry: Playback use, export events, event detail views, filter types.

Integrations: Audit event store, activity logs, storage metadata.

Acceptance criteria: User can reconstruct a meaningful path for a sensitive asset over a retained time range.

Prompt for design and prototyping

Design a lineage explorer for AccuKnox DSPM with a top playback timeline, central lineage graph, and right-side event detail panel. It should feel useful in an investigation or audit, not like a decorative activity chart.

Prompt for engineering implementation

Implement a lineage explorer with a retained event model, time-window filtering, playback controls, and export support. Optimize for large event sets by lazy-loading event detail and aggregating repeated movement steps where appropriate.

8. Compliance Cockpit

Problem statement: Security teams need regulator-facing evidence, not only generic framework badges.

Primary persona: Compliance owner, GRC analyst, CISO.

User goal: Understand which controls are failing and assemble evidence quickly.

Data requirements: Framework mappings, control status, evidence artifacts, exception status, owner assignments, attestation history.

UI composition: Regulator tabs, scorecards, control heatmap, evidence drawer, failing-asset table.

Key interactions: Switch framework, drill to control, open evidence, export report, assign owner.

States: Pass, warning, fail, evidence missing, exception active, attestation due.

Telemetry: Framework switches, control views, export frequency, evidence opens.

Integrations: Policy engine, document storage, ticketing, attestations, report generation.

Acceptance criteria: Compliance users can answer current control status and evidence completeness without manual hunting.

Prompt for design and prototyping

Design a light-theme compliance cockpit for AccuKnox DSPM with RBI, DPDP, and TRAI as first-class tabs and global frameworks as secondary options. Emphasize control status, evidence completeness, owner accountability, and export readiness.

Prompt for engineering implementation

Implement a compliance cockpit backed by framework and control mapping APIs. Support evidence attachments, missing-evidence states, owner workflows, attestation history, and export generation. Framework tabs must be extensible so regional packs can be added later without redesigning the page.

9. Drift Timeline

Problem statement: Static posture snapshots hide the operational reality of drift.

Primary persona: Security analyst, operations lead.

User goal: See how posture changed and what events caused risk movement.

Data requirements: Change events, risk deltas, owner changes, policy changes, connector activity, alert thresholds.

UI composition: Time-series chart, event stream, anomaly markers, alert settings drawer.

Key interactions: Jump to event, compare time windows, create alert, acknowledge drift pattern.

States: Stable, spike detected, acknowledged, muted, unresolved.

Telemetry: Time-window comparisons, alert creations, acknowledgements, event pivots.

Integrations: Event pipeline, notifications, alerting channels.

Acceptance criteria: Users can explain major posture movement using visible underlying events.

Prompt for design and prototyping

Design a drift timeline for AccuKnox DSPM that highlights posture movement over days and weeks. Show risk spikes, owner changes, policy drift, and notable connector or exposure events. It should feel like an operational timeline, not a generic chart dashboard.

Prompt for engineering implementation

Implement a drift timeline with aggregated and raw event views, anomaly markers, and alert configuration. Support time-window comparison, event drilldown, and integration with notification channels. Store acknowledgements so teams can track which spikes were reviewed.

10. Remediation Command Center

Problem statement: Findings are only useful if teams can close them safely and prove closure happened.

Primary persona: Security analyst, cloud security architect, operations lead.

User goal: Execute, route, or approve fixes with auditability and low risk.

Data requirements: Fix playbooks, risk reduction estimate, owner assignments, approval chain, ticket state, rollback options, audit log.

UI composition: Remediation queue, playbook detail, approval drawer, audit history, ticket panel.

Key interactions: Apply fix, request approval, create ticket, schedule change, suppress with reason.

States: Draft, pending approval, executing, succeeded, partially failed, rolled back, exception granted.

Telemetry: Actions launched, approval latency, success rate, rollback rate, suppressed items.

Integrations: Jira, ServiceNow, IAM tools, cloud APIs, approval service.

Acceptance criteria: Every remediation action leaves a visible evidence trail and can be explained later.

Prompt for design and prototyping

Design a remediation command center for AccuKnox DSPM with a queue of recommended actions, a detailed playbook pane, and a right-side approval and audit rail. Make it feel safe and controlled, not reckless. Every action should show expected risk reduction and affected assets.

Prompt for engineering implementation

Implement a remediation center with typed playbooks, approval workflows, ticket integrations, execution state updates, rollback handling, and immutable audit events. Support both one-click actions and delegated actions where the platform hands work to another team.

11. CISO Summary

Problem statement: Executives need a trustworthy narrative, not raw analyst detail.

Primary persona: CISO, VP engineering, executive sponsor.

User goal: Understand risk movement, unresolved issues, and compliance progress quickly.

Data requirements: Trend summaries, resolved issue counts, current criticals, business-unit risk rollup, compliance movement, remediation throughput.

UI composition: Narrative scorecards, trend visuals, business-unit comparison, export and schedule panel.

Key interactions: Toggle time range, export report, schedule delivery, drill into one domain.

States: Weekly summary, monthly summary, board-ready export, no movement, positive trend, negative trend.

Telemetry: Export count, scheduled recipients, time range changes, drilldowns.

Integrations: Report generation, email delivery, PDF export, stakeholder permissions.

Acceptance criteria: The page tells a coherent weekly story without requiring the sponsor to interpret analyst jargon.

Prompt for design and prototyping

Design a premium CISO summary screen for AccuKnox DSPM with strong narrative hierarchy. Show risk movement, key issues resolved, critical open items, regulator readiness change, and business-unit comparison. The screen should be exportable and sponsor-ready.

Prompt for engineering implementation

Implement a CISO summary view backed by a report-summary API with time-range comparison, business-unit rollups, and export scheduling. Ensure report widgets can degrade gracefully when source detail is unavailable and that exports preserve the on-screen narrative order.

12. CNAPP x DSPM Risk Correlation

Problem statement: AccuKnox's strongest differentiator is only valuable if users can see it and trust it.

Primary persona: Security analyst, cloud security architect, product champion.

User goal: Understand which data risks are amplified by cloud posture or runtime signals and therefore deserve higher urgency.

Data requirements: Sensitive asset posture, cloud misconfiguration state, runtime signals, reachable attack paths, exposure history, incident links.

UI composition: Correlation matrix, causal timeline, related asset panel, unified incident launcher.

Key interactions: Pivot between data and cloud view, inspect correlation rationale, open unified incident, compare related assets.

States: High-confidence correlation, weak correlation, missing runtime context, incident linked, remediated.

Telemetry: Correlation drilldowns, incident launches, related asset pivots, confidence threshold changes.

Integrations: CNAPP posture APIs, runtime telemetry, incident management, graph services.

Acceptance criteria: Users can explain why a data risk is ranked higher because of cloud or runtime context, not just because the data is sensitive.

Prompt for design and prototyping

Design a unique AccuKnox screen that correlates DSPM findings with CNAPP and runtime signals. Use a correlation matrix, causal timeline, and an incident action rail. The design should make the differentiation obvious in one glance: this is not just a data inventory screen, it is a risk-operating surface.

Prompt for engineering implementation

Implement a correlation view that joins DSPM findings with CNAPP posture and runtime telemetry using typed correlation objects with confidence scoring and rationale fields. Support drilldowns, incident creation, and side-by-side comparison of related risky assets. Preserve explainability so the score uplift is auditable.
