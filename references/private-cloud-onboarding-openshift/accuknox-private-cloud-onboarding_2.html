Before you start

AccuKnox scans your OpenShift Virtualization VMs from inside the cluster, with no agent in the VMs. Confirm these four things first, the scan fails without them.

  • A VolumeSnapshotClass object exists in the cluster. The scanner snapshots each VM's volume instead of touching the running VM.
  • At least one VolumeSnapshotClass is marked default. The scanner uses the default class when it creates snapshots.
  • All VMs on the cluster use the same CSI driver. Usually already true. Clusters rarely run two storage solutions side by side.
  • You have cluster-admin on the cluster. You will add a catalog source and install a cluster-wide operator.
Five steps, about 15 minutes. Four happen in the OpenShift console, one happens here.
In the OpenShift console

Add AccuKnox to the operator catalog

The AccuKnox operator isn't in the OpenShift Software Catalog by default, so you add its catalog first. Full walkthrough with screenshots

This would open the Help Docs walkthrough in a new tab.

  1. Log in to your OpenShift web console

    This would open your OpenShift console in a new tab.

  2. Go to Administration → Cluster Settings → Configuration and search for "OperatorHub"

  3. Open OperatorHub → Sources, then click Create CatalogSource

  4. Fill in the form

    CatalogSource name
    Anything, for example accuknoxscanner
    Display name
    Anything, for example AccuKnox Scanner
    Publisher name
    accuknox
    Availability
    Cluster-wide CatalogSource, which is already the default
    Image (URL of container image)
    public.ecr.aws/k9v9d5v2/omni-operator-index:v0

  5. Click Create, then wait for the source to show READY

    Anything other than READY means the cluster couldn't pull the catalog image. Check egress and any registry mirroring policy.

Leave Availability on Cluster-wide. A namespaced catalog source only exposes the operator in one namespace, and the scan needs to reach VMs across the cluster.
In the OpenShift console

Install the operator

Now that the catalog is added, the operator is installable in one click.

  1. Go to Ecosystem → Software Catalog and search for accuknox

    The tile is called AccuKnox VM Scanning.

  2. Open the tile and click Install

  3. Keep every default on the Install Operator page, then click Install again

    That includes the installed namespace, openshift-operators. Note whichever namespace you end up with, you'll need it twice more.

  4. Wait for it to appear under Ecosystem → Installed Operators

    Takes a couple of minutes. When it's done the operator lists two provided APIs, Scan and Schedule.

token → secretRef → key

cronJobNamespace
The namespace the secret lives in, for example openshift-operators

        


        
When and how it runs

        

          
schedule
A cron expression, for example 0 2 * * * for 2 AM daily

          
timeZone
A tz database name such as Asia/Kolkata. Case-sensitive.

          
concurrency
How many VM scans run at once. Start with 1.

          
template → clusterName
Any name. Becomes the asset name for these findings in AccuKnox.

          
scansHistoryLimit
How many finished scans to keep. Defaults to 3.

        


        

          
          Every VM in the cluster is scanned, and discovery reruns on every execution, so new VMs are picked up with no config change. To scan a subset, create more than one schedule and give each a VM label selector.
