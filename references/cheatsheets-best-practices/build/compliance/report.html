Root causes

Point in time audits
miss what changes daily

Cloud resources change on every deploy. An audit checks one day, so four habits leave the gaps in place.

Each framework is its own project
97% of firms run at least two audits a year. When CIS, SOC 2 and PCI DSS each get a separate spreadsheet, the team tests and documents one control three times.
Evidence is gathered by hand
A screenshot taken in audit week proves the state of one day. Leaders in the Vanta survey say automation would save 3 to 5 hours each week.
Scope stops at the cloud account
CIS publishes separate benchmarks for Kubernetes and for each operating system. A cloud account scan reads the provider API and checks neither one.
Failed controls have no owner
A failed check with no ticket and no due date stays failed. The next change to the account adds new drift on top of it.

Practice 01

Map each control once,
report it to every framework

AccuKnox ships more than 1,000 checks, and each check maps to the sub controls of one or more compliance programs.

Compliance Frameworks catalog. help.accuknox.com/use-cases/compliance/

Do
  • Open Browse Frameworks and turn on each framework you report against, such as SOC 2, ISO 27001, PCI DSS or HIPAA.
  • Fix a failed check once. The next scan updates the result in every framework that maps to it.
  • Add internal policy with Create Custom, so company controls sit beside the standards.
  • Run one Cloud Compliance report for one account across several frameworks, such as HIPAA and APRA 234.
Don't
  • Don't keep a separate control spreadsheet for each framework.
  • Don't open one ticket per framework for the same failed check.
  • Don't assume every framework covers every cloud. The support matrix lists AWS Well Architected for AWS only.

Practice 02

Collect evidence on
every scan, not in audit week

Each scan scores every control and keeps the history, so last quarter's record exists before the auditor asks.

Benchmark insights with score trend and checks per control. help.accuknox.com/use-cases/compliance/

Do
  • Onboard every cloud account, so scans run on a schedule with no person starting them.
  • Read the score per sub control. It equals passed checks over passed, failed, warning and not available checks.
  • Filter the Detailed View by account, region and severity to give the auditor the exact scope.
  • Let the lifecycle close findings. A finding absent from two scans in a row moves to Fixed.
Don't
  • Don't collect screenshots the week before the audit.
  • Don't treat Warning or Not available as a pass. Both count against the score.
  • Don't ignore a finding to lift the score. Mark it Accepted Risk or Exception Requested, so the decision stays on record.
How AccuKnox closes the gap

The findings lifecycle sets each status from scan results and keeps a history of actions on every finding. Read the findings lifecycle

Practice 03

Cover the workloads,
not only the cloud account

Kubernetes clusters and VMs carry their own CIS and STIG controls, and a cloud account scan does not read them.

CIS Kubernetes Benchmark finding with SLA and failing since date. help.accuknox.com/how-to/cis-benchmarking/

Do
  • Turn on the Kubernetes CIS Benchmarking job in Settings, Manage Clusters, and set a scan schedule.
  • Install the VM Scanner with Knoxctl for CIS or DISA STIG profiles on Ubuntu 22.04 and 24.04.
  • Filter Issues, Findings by CIS k8s Benchmarking or STIG to review workload results.
  • Review manual controls yourself. 541 of the 1020 VM controls need human judgement.
Don't
  • Don't read a skipped control as a pass. The scanner reports manual controls as skipped.
  • Don't expect CIS Kubernetes results on every distribution. The docs list managed GKE clusters today.
  • Don't onboard a cluster without a label. The CIS job uses the label to identify the cluster.

One platform covers cloud, workload and AI compliance, with agentless scans for public cloud and agents for private and air gapped sites. Set up VM benchmarking

Practice 04

Schedule the report
before the auditor asks

Scheduled reports run daily, weekly or monthly and go by email to every recipient you name.

Reports with scheduled and on demand compliance reports. help.accuknox.com/how-to/custom-reports/

Do
  • Create a Cloud Compliance Report from Browse Report Templates and set it to Scheduled.
  • Match the date range to the audit period, such as the last 14 or 30 days.
  • Add the GRC lead and each control owner as email recipients.
  • Run one framework across many accounts when the auditor scopes by standard.
Don't
  • Don't build the audit pack by hand from CSV exports.
  • Don't wait for audit week to ask for a custom template. AccuKnox Support configures custom templates first.
  • Don't send an export with no date range. The auditor needs the period it covers.
How AccuKnox closes the gap

Scheduled CSPM and ASPM reports are versioned and status tracked, which gives SOC 2 and ISO 27001 audits consistent evidence. Configure scheduled reports

Practice 05

Give every failed control
an owner and a ticket

A finding with no owner stays open. Route each failed check to the team that can fix it.

Failed check with Create Ticket and its mapped frameworks, account redacted. help.accuknox.com/how-to/findings-lifecycle/

Do
  • Connect Jira, ServiceNow or another ticketing tool, then open tickets from the finding.
  • Write a Rules Engine rule that opens a ticket for every new critical compliance finding.
  • Set an expiration on each rule, and review the rule before it lapses.
  • Use In Progress, Waiting for 3rd Party and Accepted Risk, so the status tells the auditor what happened.
Don't
  • Don't let critical findings sit unticketed. The summary report counts them.
  • Don't mark Accepted Risk without a comment that names who approved it and why.
  • Don't close a ticket before the next scan confirms the fix.
How AccuKnox closes the gap

The Rules Engine applies one rule to every matching finding, so a new failure reaches its owner with no manual triage. Automate ticket creation

Practice 06

Track drift between
audits, not after them

Compare each scan with the last one, and alert when a critical asset changes.

Compliance summary with last scan score and change per framework. help.accuknox.com/use-cases/compliance/

Do
  • Check the change value on the compliance summary after each scan.
  • Group critical assets and apply a baseline conformance check on a schedule.
  • Set Monitors on assets such as S3 buckets and bastion hosts to alert on any configuration change.
  • Read the weekly trend of new and critical findings in the summary report.
Don't
  • Don't wait for the annual audit to learn that a score dropped.
  • Don't fix drift only in the console. Fix the IaC template too, or the next deploy brings the drift back.
  • Don't put a Monitor on every asset. Start with the assets in audit scope.
