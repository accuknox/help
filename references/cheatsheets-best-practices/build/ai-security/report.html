Root causes

Four gaps keep
AI risk growing

AI arrives before the inventory

A developer adds an AI SDK, an agent or an MCP server in one pull request. Only 37% of organizations have policies to manage AI or detect shadow AI.

Attackers enter around the model

In AI breaches, compromised APIs, apps or plugins caused 27%. Cloud misconfigurations that affect AI workloads caused another 27%.

Agents hold more power than the task needs

OWASP names excessive functionality, permissions and autonomy as the root causes of Excessive Agency, risk LLM06 in its 2025 list.

Models and prompts ship untested

OWASP says a public model can carry a hidden backdoor. It also says no known method fully prevents prompt injection, so every model and app needs a test.

Practice 01

You cannot secure an AI
asset you never found

AI-SPM and Shadow AI Discovery list every model, agent and MCP server in cloud and on premises.

Unmanaged AI assets by category. help.accuknox.com/use-cases/shadow-ai-discovery/

Do
  • Onboard every AWS, Azure and GCP account with AI Security on, then review the Managed tab.
  • Run the VM and in cluster scanners to find unmanaged AI SDKs, agents and MCP servers.
  • Assign an owner to each AI asset and triage critical findings first.
  • Review the inventory weekly, because teams add AI packages faster than they file tickets.
Don't
  • Don't trust a spreadsheet of approved AI tools as your inventory.
  • Don't scan only production. Notebooks and dev clusters hold AI packages too.
  • Don't treat discovery as enforcement. Discovery shows the asset, and the other five controls govern it.
How AccuKnox closes the gap

Shadow AI Discovery connects through a read only cloud API and package level scanners, then maps each package to an AI asset type. Set up Shadow AI Discovery

Practice 02

Watch the AI control plane,
not only the model

AI-DR reads cloud audit events and alerts on risky AI changes, such as a public Azure OpenAI resource.

AI-DR detects a public Azure OpenAI resource and triggers remediation. help.accuknox.com/how-to/azure-aidr/

Do
  • Feed CloudTrail on AWS and Event Hub on Azure into AccuKnox for every AI account.
  • Alert on new SageMaker notebooks, Bedrock customization jobs and Azure ML workspace changes.
  • Route alerts to a webhook or Jira, and wire automated remediation for known bad states.
  • Treat a deleted Azure OpenAI resource as a critical event and confirm who did it.
Don't
  • Don't give data scientists admin rights to create public AI endpoints.
  • Don't rely on AI-DR to stop a bad prompt. AI-DR runs out of band and never sits in the inference path.
  • Don't let AI alerts land in a queue nobody owns.
How AccuKnox closes the gap

AI-DR raises the alert, opens the ticket and can trigger remediation. The Prompt Firewall covers the inference path. Set up AI-DR on Azure

Practice 03

Give an agent only the
access its task needs

ModelArmor sandboxes agents and MCP servers in the kernel with eBPF and LSM, with no code change.

Managed agents with their knowledge bases and tools. help.accuknox.com/getting-started/3.5-release/

Do
  • Inventory every agent, its knowledge bases and its tools before you add guardrails.
  • Apply process, file system, network and domain isolation to each agent runtime.
  • Allow list the domains and binaries an agent may reach, and deny the rest.
  • Block reads of credential files such as /root/.aws/credentials from agent processes.
Don't
  • Don't run an agent or MCP server with the host's full network and file access.
  • Don't give one agent private data, untrusted content and outbound access at the same time.
  • Don't install a community MCP server without review and a sandbox.

Practice 04

Scan a model before
it loads, not after

A model file can carry code. An unsafe pickle runs that code the moment you load it.

ML Static Scan findings, including an unsafe operator in a pickle file. help.accuknox.com/how-to/ml-static-scan/

Do
  • Run ML Static Scans on every model from GitHub or Hugging Face before first use.
  • Treat model file security findings, such as an unsafe pickle, as blocking.
  • Gate new models in CI/CD with the /scan pull request comment, and merge only on a clean report.
  • Rescan on every model version bump.
Don't
  • Don't load a public model straight into a production notebook.
  • Don't commit model weights to the repo. Name the model in the pull request instead.
  • Don't assume a static scan covers runtime. It does not test behavior or inference time attacks.
How AccuKnox closes the gap

ML Static Scans check supply chain, resistance to adversarial inputs, data and privacy risk and model file safety. ModelArmor contains a model at runtime. Add model scans to CI/CD

Practice 05

Attack your own LLM
before an attacker does

Red teaming runs adversarial probes against your model and records each prompt that broke it.

AI red teaming findings for Amazon Bedrock models. help.accuknox.com/how-to/aiml-bedrock-collector/

Do
  • Scan every LLM app across Sentiment, Code, Hallucination and Prompt Injection.
  • Schedule scans on a cron, and rerun after each model, prompt or config change.
  • Upload your own prompts JSON to test domain risks.
  • Fix findings from Issues > Findings > LLM Findings, and open a Jira ticket per risk.
Don't
  • Don't ship an LLM app after one manual test.
  • Don't ignore package hallucination. A fake package name in AI generated code is a supply chain risk.
  • Don't treat a clean scan as permanent. A new model version resets the result.
How AccuKnox closes the gap

Findings map to OWASP Top 10 for LLMs and MITRE ATLAS, and each one shows the probe, the detector and the response. Run your first red team scan

Practice 06

Inspect every prompt
and every response

The Prompt Firewall sits inline between users and the LLM, and blocks, sanitizes or monitors each message.

Prompt Firewall view of one LLM app, with violations by action and severity. help.accuknox.com/use-cases/prompt-firewall-overview/

Do
  • Start policies in Monitor mode for one week, then move proven policies to Block.
  • Turn on Anonymize, Secrets and Prompt Injection for every app.
  • Pass a session ID so stateful tracking catches jailbreaks spread over many turns.
  • Deploy the browser plugin to Chrome, Edge and Firefox for staff who use ChatGPT, Claude, Gemini or GitHub Copilot.
Don't
  • Don't treat the firewall as the only control. Guardrails are probabilistic and miss some attacks.
  • Don't scan only prompts. Inspect responses for PII, secrets and unsafe code too.
  • Don't assume the plugin covers apps. The plugin sees browser traffic only, so instrument apps through the SDK or a gateway.
How AccuKnox closes the gap

Connect through the SDK or a gateway such as LiteLLM, Azure APIM or AWS API Gateway, and choose from 14 policy types. Read the Prompt Firewall guide

Use AI well

Get the speed
of AI without the
data leak

Security also covers how people use AI every day. Give these rules to every engineer and analyst.

Do
  • Use the AI tools your company approved, signed in with your work identity.
  • Mask customer data and secrets before you paste a log or a config into a prompt.
  • Review AI generated code like a pull request from a new hire, then run it through your scanners.
  • Check that every package an AI tool suggests exists before you install it.
Don't
  • Don't paste API keys, tokens or passwords into any chat assistant.
  • Don't upload confidential documents to a personal AI account.
  • Don't let a coding agent run with your cloud admin credentials.
  • Don't connect an MCP server or browser extension your security team has not reviewed.
