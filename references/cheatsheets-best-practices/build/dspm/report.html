Root causes

Four reasons sensitive
data stays exposed

Copies outrun the inventory
Teams copy data into new buckets, databases and SaaS apps every week. The average enterprise now runs 85 SaaS applications. A list kept by hand misses the newest copy first.
A name hides the content
A bucket named logs can hold card numbers. Customer PII was 52% of the data stolen or exposed in 2026 breaches, at $192 per record. Only a scan of the content shows it.
Encryption lacks context
Only 8% of organizations encrypt 80% or more of their cloud data. A posture check that cannot see which store holds PII cannot tell you which unencrypted store to fix first.
Findings have no owner
Breaches took 247 days on average to identify and contain in 2026. A data finding with no severity, SLA or ticket waits in the queue while the copy stays open.

Sources. 85 SaaS apps and 8%: Thales 2025 Cloud Security Study, press release and blog. 52% and $192: IBM Cost of a Data Breach 2026, via Network World. 247 days: IBM Cost of a Data Breach 2026, via Help Net Security.

Practice 01

Scan every data store,
not only the known ones

Scope an S3 source. help.accuknox.com/getting-started/dspm-overview

Scope each S3 source by tag and name pattern, then scan every public bucket whatever its name.

How AccuKnox closes the gap

The scanner runs as a VM or Kubernetes CronJob in your account. It reads a sample each night and sends one findings file per data store. Onboard the DSPM scanner

Do
  • Turn on Data Security for each AWS account and Azure subscription, then add each store as a source.
  • Select S3 buckets by tag and by name pattern, such as env = prod or *customer.
  • Check Scan Publicly Exposed buckets. It scans every public bucket, even outside your patterns.
  • Run one scanner per region, because a scanner never reads data in another region.
Don't
  • Don't scan only the buckets on a team's list. New copies land outside that list.
  • Don't give the scanner write access. Every grant it needs is read only.
  • Don't assume full coverage. Google Cloud Storage, NFS shares, Oracle and Snowflake are not supported yet.

Practice 02

Classify by content,
not by store name

Evidence per file in one asset. help.accuknox.com/getting-started/dspm-overview

The scanner reads each file and row, then tags what it finds, such as Aadhaar, card and bank account numbers.

How AccuKnox closes the gap

283 data classes cover PII, PHI, financial data, credentials and national IDs, each with a confidence tier. See what the scanner detects

Do
  • Enable the country packs for the countries you operate in. They decide which national IDs and phone formats match.
  • Keep the confidence floor at Likely. Raise it to Very likely for fewer, stronger findings.
  • Put public phone numbers, test accounts and sample data on the allow list.
  • Let AccuKnox AI review the results to cut false positives.
Don't
  • Don't trust a bucket name or tag to say what the bucket holds.
  • Don't ignore a value in the console only. Add it to the allow list, or it returns on the next run.
  • Don't keep detectors you never need. Switch them off to cut noise.

Practice 03

Close public and
unencrypted stores first

Asset overview with security configuration. help.accuknox.com/getting-started/dspm-overview

Each asset shows its sensitive records beside its encryption and public access settings, so you fix the riskiest stores first.

How AccuKnox closes the gap

DSPM shows which store holds the data. CSPM flags the public S3 bucket or the unencrypted volume behind it. Fix S3 public exposure

Do
  • Filter for the findings A data asset is public and An unencrypted data asset can be accessed by identities.
  • Open each asset and read Security Configuration for encryption and public access.
  • Block public access on each S3 bucket that holds sensitive records, then confirm the finding clears.
  • Turn on default encryption for stores that hold PII, PHI or card data.
Don't
  • Don't fix exposure in the order findings arrived. Rank by sensitive record count.
  • Don't leave a public copy behind after you lock down the main store.
  • Don't grant broad read roles to reach a store faster. Check which identities can already read it.

Practice 04

Work findings by severity,
sensitivity and SLA

Each finding carries a severity, an SLA window and a sensitivity label, so the queue has an order before anyone reads it.

A Critical finding with SLA and sensitivity. help.accuknox.com/getting-started/dspm-onboarding

Do
  • Start with Critical and Restricted findings, then the largest match counts, then the oldest against SLA.
  • Raise a ticket in your tracker from the finding with Create Ticket.
  • Follow the Solution tab for the remediation and its references.
  • Confirm the fix when Last detected stops advancing after the data is masked, moved or deleted.
Don't
  • Don't copy raw values into a ticket. Data Matches already masks each value to its last four characters.
  • Don't turn on Ignored unless you confirmed the value is public or test data.
  • Don't let a Critical finding pass its SLA. The SLA for this Critical finding is 10 days.
How AccuKnox closes the gap

Practice 05

Stop sensitive data
at the AI prompt

The Prompt Firewall sits inline between users and the LLM, and masks or blocks sensitive data in both directions.

Prompt Firewall policy types. help.accuknox.com/use-cases/prompt-firewall-overview

Do
  • Turn on Anonymize to mask names, SSNs, emails, medical records and card numbers.
  • Turn on Secrets to block API keys, tokens and passwords before the LLM sees them.
  • Inspect responses too, so sensitive content never reaches the end user.
  • Add Regex patterns for internal IDs and custom formats.
Don't
  • Don't treat the firewall as the only control. Guardrails are probabilistic and miss some attacks.
  • Don't let staff paste customer records into unapproved AI tools.
  • Don't block on day one. Monitor first, then block once the policy proves itself.
How AccuKnox closes the gap

Every prompt and response passes the firewall, which blocks, sanitizes or monitors it and logs it for audit. Read the Prompt Firewall guide

Practice 06

Show auditors where
regulated data sits

A finding mapped to PCI DSS, SOC 2 and HIPAA. help.accuknox.com/getting-started/dspm-overview

282 of 283 data classes carry the regulation clauses they fall under, from GDPR and PCI DSS to HIPAA and India DPDP.

How AccuKnox closes the gap

Frameworks include GDPR, UK GDPR, PCI DSS, HIPAA, CPRA, India DPDP, POPIA, PIPEDA and the NIST SP 800 series. See the compliance mapping

Do
  • Filter findings by framework to list every asset that holds data under it.
  • Enable the country packs that match your regulators, because coverage follows the packs.
  • Use the Classification tab for each class's CWE and MITRE ATT&CK references.
  • Run the console on premises or air gapped when data must stay inside your boundary.
Don't
  • Don't present the data map as a controls audit. DSPM shows where regulated data sits, not how well its controls work.
  • Don't hand auditors raw values. The console masks each value to its last four characters.
  • Don't scan only before the audit. Nightly runs record when each finding cleared.
