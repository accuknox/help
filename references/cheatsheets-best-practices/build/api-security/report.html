Root causes

Four gaps keep
APIs exposed

The inventory lives in documents
54% of organizations rely on developer documentation to find sensitive data exposure. A route a developer ships on Friday is missing from that document on Monday.
Old versions keep answering
A V1 endpoint replaced by V2 can still take live calls, often with weaker authentication. OWASP lists this risk as API9:2023 Improper Inventory Management.
Nobody watches live traffic
80% of organizations lack continuous, real time API monitoring. A quarterly review misses the route a team added this week.
Findings have no owner
87% of organizations in the Akamai survey reported an API security incident in 2025. A finding with no ticket and no owner stays open until an attacker finds it.

Sources: Salt Security, H2 2025 State of API Security Report, salt.security. OWASP API Security Top 10 2023, api-security.owasp.org. Akamai 2026 SOTI release, akamai.com.

Practice 01

Build the inventory
from live traffic

AccuKnox reads gateway and mesh logs and lists every endpoint it sees, with method, path, exposure and auth type.

API Security inventory with discovered APIs and sensitive data types. help.accuknox.com/use-cases/api-security/

Do
  • Connect every gateway and mesh: AWS API Gateway, the K8s API proxy, Istio, NGINX, Kong and F5.
  • Deploy the AWS API Gateway stack once per stage, so Dev, Staging and Prod all feed the inventory.
  • Filter to External and Unauthenticated endpoints first, because attackers reach those.
  • Group endpoints into collections by host, method or path regex, one per owning team.
Don't
  • Don't build the inventory from a wiki page or a gateway config export.
  • Don't watch only the edge gateway. Service calls inside the mesh carry data too.
  • Don't treat the inventory as a one time count. It changes as new logs arrive.
How AccuKnox closes the gap

API Security builds the inventory from gateway logs with no code change, and creates a collection from each host endpoint on its own. Connect a traffic source

05
Practice 02

Make the OpenAPI spec
your baseline

A scan compares observed endpoints against the spec, so the spec decides what counts as drift.

API Specification page with an OpenAPI 3.0 file open. help.accuknox.com/how-to/api-security-onboarding/

Do
  • Upload every OpenAPI or Swagger file in JSON or YAML, up to 3 MB each.
  • Generate a spec from observed traffic for any API that has none, then hand it to the owning team.
  • Upload the new spec in the same release that changes the API.
  • Rename a file before upload when you want to keep the old version.
Don't
  • Don't reuse an existing file name by accident. The upload replaces the old file.
  • Don't trust a spec written once at launch. Routes change faster than documents.
  • Don't skip the spec. The spec is the baseline that sorts Shadow from Active APIs.
How AccuKnox closes the gap

API Security stores each spec under API Security > API Specification, and generates an OpenAPI spec from traffic for an API with no documentation. Upload your first spec

Practice 03

Hunt shadow, zombie
and orphan APIs

A spec scan sorts each endpoint into Shadow, Zombie, Orphan or Active, with request and response detail.

API Security Findings with Shadow API and Orphan API rows. help.accuknox.com/how-to/api-security-onboarding/

Do
  • Triage Shadow APIs first. They take production traffic and no spec covers them.
  • Retire each Zombie API, a deprecated version that still answers calls.
  • Confirm each Orphan API with its owner, then remove it from the spec or the code.
  • Scan per collection, so each team sees only its own drift.
Don't
  • Don't add a shadow endpoint to the spec before you check who calls it and what it returns.
  • Don't leave a V1 route live after V2 ships.
  • Don't read an empty Shadow list as safe while some gateways stay unconnected.
How AccuKnox closes the gap

Shadow, zombie and orphan detection addresses OWASP API9:2023 Improper Inventory Management. Each finding shows the request, the response and the occurrence count. Read the finding types

Practice 04

Know which
APIs carry
sensitive data

Each endpoint lists the sensitive parameters AccuKnox found in its request and in its response.

The Contribution to Risk panel names why an endpoint ranks high, such as high sensitivity of data, recent discovery or public accessibility.

Endpoint detail with sensitive params and risk factors. help.accuknox.com/how-to/api-security-onboarding/

Do
  • Filter the inventory by Sensitive Params such as api_key, password, token and JWT.
  • Check the response, not only the request. A response can return data the caller never asked for.
  • Raise priority when an endpoint is external, unauthenticated and sensitive at once.
  • Review the Top 5 Sensitive Datatype chart every week for new data types.
Don't
  • Don't rely on developer notes to tell you which endpoints carry PII.
  • Don't pass API keys or passwords in a query string or a URL path.
  • Don't treat a Bearer token as enough when an endpoint returns another user's object. OWASP calls this API1:2023 Broken Object Level Authorization.
How AccuKnox closes the gap

API Security classifies sensitive data in each request and response, and labels each endpoint as internal or external. Open endpoint telemetry

Practice 05

Scan on a schedule
and test the live API

A spec scan finds drift. The API Scan collector sends active tests to a running target URL.

Scan list and the New Scan form. help.accuknox.com/how-to/api-security-onboarding/

Do
  • Set each spec scan to Scheduled, so drift shows up without a reminder.
  • Run both paths. The spec scan finds undocumented endpoints, and the collector finds weak responses.
  • Point the API Scan collector at a staging target first, with a label and a notification email.
  • Give each scan a label so findings group by team or service.
Don't
  • Don't expect a spec scan to find a source code disclosure. Only the collector tests live responses.
  • Don't run active tests against production without the service owner's approval.
  • Don't ignore a scan stuck at Error. Fix the file or the target, then rerun it.
How AccuKnox closes the gap

Spec scans run on demand or on a schedule. The API Scan collector takes its endpoints from an uploaded spec, a collection or a spec URL. Set up both scan paths

Practice 06

Route every finding
to an owner

Each API finding opens with Create Ticket and Ask AI, and a Rules Engine rule can file the ticket for you.

Orphan API finding with Create Ticket and Ask AI. help.accuknox.com/use-cases/rules-engine-ticket-creation/

Do
  • Write a Rules Engine rule that opens a Jira ticket for every Critical Shadow API.
  • Use Ask AI on a finding to draft the fix for the owning team.
  • Track the SLA and the status of each finding until the fix is verified.
  • Rate limit login and checkout endpoints against API4:2023 Unrestricted Resource Consumption.
Don't
  • Don't let API findings land in a shared inbox nobody owns.
  • Don't mark a finding as ignored without a note that says why.
  • Don't start a new rate limit in Block. Run it as Alert first to learn normal traffic.
How AccuKnox closes the gap

Rate limits apply per user or IP per endpoint, per user or IP across the app, or per service, with a Block or Alert action. Automate ticket creation
